# 守卫与卡点提醒效果评测方案（预登记草案 v1）

日期：2026-09-30。目的：证明 Progress Guard（收尾守卫）与 Convergence
Reminders（卡点/收敛提醒）对 agent 完成质量有因果效果。
本文为预登记文件：主指标、臂结构、排除规则在实验开始前冻结；
事后不得更换指标或子群重新解读。

## 0. 已有证据与缺口（为什么需要这个方案）

| 主张 | 现有证据 | 缺口 |
|---|---|---|
| 信号可预警失败 | 离线回放 P=0.908 / R=1.0（233 run） | 仅单模型（mimo）、单任务族 |
| 守卫直接效应 | 协议采纳 0%→54%；守卫臂 10/10 跑了 pytest | 行为改变 ≠ 完成率 |
| 收敛提示 uplift | +13.3pts（p=0.68，n=15/臂） | 被伪调用混淆；功效不足 |
| 伪调用已修复 | PseudoCallGuard 52 测试绿 | 真实 run 上的修复率未测 |

结论：需要一次消除已知混淆、功效达标、分机制归因的对照实验。

## 1. "有效"的四层定义（分层证明，不得互相替代）

| 层 | 定义 | 指标 |
|---|---|---|
| L1 无害性 | 干净任务上零误伤 | 零守卫投递率、完成率不降 |
| L2 预警质量 | 提醒打得准 | 提醒精确率/召回（对照最终结局）、触发时机 |
| L3 直接效应 | 提醒改变行为 | 验证执行率、协议采纳率、投递后验证转化率 |
| L4 远端效应 | 行为改变转化为结果 | **部分得分完成率**（主指标，见 §3） |

## 2. 前置门禁（不满足不进入主实验）

1. **伪调用率门禁**：预跑 6 run，PseudoCallGuard 触发后编辑落盘率 ≥90%
   （Phase 2a 为 ≤30/30 中 10 落盘）。不达标先修 harness，测 uplift 无意义。
2. **难度带校准**：trap-ladder 重校准，主任务集 baseline 完成率落 30-70%
   （GUARD_EFFECT_REPORT §7 方法）；低于 30% 的任务族不进主实验
   （历史教训：baseline≈0 时 uplift 恒为 0）。
3. **基础设施**：模型/网关身份断言（freellm 的 model_identity 模式）、
   环境错误显式透传并从完成率分母排除（排除规则预登记）、
   API 配额充足（Phase 3 教训：30 run 中止于额度）。

## 3. 实验设计（2×2 因子，任务配对，多种子）

### 任务集（三族，共 24 个任务 × 每任务 3 seeds）

| 族 | 目标失败模式 | 数量 | 检验对象 |
|---|---|---|---|
| V 族：验证缺口 | 做了不验证（单 bug，修完不跑测试） | 8 | Guard |
| S 族：停滞 | 复合任务易卡（c3 型三 bug） | 8 | 收敛提醒 |
| C 族：干净 | 简单直接任务 | 8 | L1 无害性 |

族内任务按历史 pass 率分层配对；所有任务逐测试可独立判定
（修复 Phase 2 部分得分不可检验的缺口）。

### 臂（4 臂 × 24 任务 × 3 seeds = 288 run，~2-5min/run ≈ 12-24h，分晚跑）

| 臂 | 插件 | 说明 |
|---|---|---|
| control | --no-extensions | 纯基线 |
| guard | 收尾守卫 advisory | 只测 Guard |
| conv | 收敛提醒 advisory | 只测收敛 |
| both | 两者 | 测叠加/干扰 |

control 臂与干预臂同晚交替执行（防漂移）；模型/网关锁定并记录身份。

### 主指标（预登记）

- **主**：部分得分完成率（per-goal credit / goals，终局 judge 复测 pytest
  为准——模型自证完成仅 1/30 的教训）。分层：S 族与 V 族分开报告。
- 次级：L1-L3 各项、提醒精确率（提醒后仍未完成的比率）、
  静默停止率、first-verify 时间、截断/伪调用残留率。
- 分析：任务配对 McNemar（二值）+ 配对置换检验（部分得分）；
  全部比例报 Wilson 95% CI；分层分析与合并分析同时报告
  （历史教训：合并 uplift 可能被族间抵消掩盖）。

### 功效声明（诚实条款）

n=24×3=72/臂：在 baseline 33% 下可检出 **≥+19pts**（80% 功效）；
配对设计实际功效更高但要到数据才能算。若要检出 +10pts 需 ~150 run/臂。
分两阶段：先跑 12 任务 × 3 seeds（144/臂）看方向与 L2/L3，
效应方向为正且 L2 精确率 ≥0.7 再补满 24 任务。

## 4. 归因规则（防止又把混杂当效果）

- 每个 run 记录：伪调用残留、投递时机/内容/后继行为、截断签名、
  环境错误、模型身份——任一污染指标进排除清单（预登记）。
- 提醒效果单列"投递 run 内对照"：投递前后验证行为变化 +
  未投递同族任务对照；明确声明存活混淆方向。
- L4 结论仅在"伪调用率门禁通过 + 污染排除后"的样本上出具；
  不足量跑满就报 under-powered，不出具"无效"结论
  （区分"证明无效"与"没证明有效"）。

## 5. 成本与执行

- mimo-v2.5（$0.00004/次）：288 run 总成本 ≈ $0.01 级，瓶颈纯为墙钟时间；
  备选：Kilo 免费池（零成本但有 429 风暴前科，须 model_identity 把关）。
- 执行序列：前置门禁（~30min）→ 阶段一 144 run（~6h）→
  方向判定 → 阶段二补满（~6h）→ 分析报告。
- 产物：results/guard-effect-v2/（runs.jsonl 逐例、metrics、
  归因、预登记对照表）；全部会话留存。

## 6. 成功标准（预登记）

- 守卫有效 = V 族 L4 完成率 +≥10pts（配对检验 p<0.05）**且**
  L2 提醒精确率 ≥0.7 **且** C 族零误伤。
- 收敛提醒有效 = S 族同上标准。
- 任一臂 L1 违例（干净任务误伤 >0）→ 该干预标记为不可上线，
  无论 L4 数字多好。
- 结论措辞模板预写：显著 / 方向正但欠功效 / 无效 三选一，禁止事后改口。

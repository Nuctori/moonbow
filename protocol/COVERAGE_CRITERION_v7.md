# 证据强度判据 v7（正式修订版）2026-09-18

> **本版替代 v6。** v6 的三值结构不变，但**层间职责划分被 §258–§259 的审计改写**。

## 一、修订缘由：v6 的职责划分建立在被污染的比较上

v6 隐含的职责划分是：
```
程序（机械闸）：无产物 token ⇒ NONE
模型（语义）：  STRONG vs MEDIUM
```
该划分的依据是 §254/§255 的实测（模型 NONE 召回 0.000，程序 0.857）。
**§258 证明该对照无效**：程序 token 表由评估集标注反推，在评估集上被优待
（训练 0.589 vs 评估 0.839，落差 0.250）。

**§259 去污染后结论反转**：
| 标注集 | 独立程序 | 模型 | Δ |
|---|---|---|---|
| v5b_A | 0.675 | **0.768** | +0.094 (p=0.013) |
| v5b_B | 0.774 | **0.814** | +0.040 |
| v5c_A | 0.730 | **0.816** | +0.087 (p=0.024) |
| v5c_B | **0.741** | 0.717 | −0.024 (p=0.60) |

⇒ **模型在 3/4 集领先，2 集显著。**

## 二、v7 正式划分

```
层 0（必须由程序承担，理由改变）
  产物 token 的**抽取**：正则扫描 work_log，产出 token 集合。
  理由：这是纯字符串操作，模型无优势；且模型输出不稳定。
  注意：**不是**因为"模型学不会 NONE"，而是因为抽取是确定论任务。

层 1（模型承担，已去污染对照验证）
  STRONG vs MEDIUM 的分档。
  理由：模型 3/4 集领先独立校准的程序规则，2 集显著。

层 2（NONE 判定，**两边都不可靠** —— v6 的错误在此）
  v6 称"无 token ⇒ NONE，交还程序"。§259 证明**程序在 NONE 上同样差**：
  独立程序在训练集把 MEDIUM 误判为 NONE 达 283/700 = 0.404。
  ⇒ NONE 不是"程序可靠、模型不可靠"，而是**该界对两者都困难**。
  v7 处置：NONE 判定保留为**独立可配置项**，不预设由谁承担；
  其可靠性取决于 token 抽取的召回率，而当前 token 表**未经独立验证**。
```

## 三、模型层有效刻度（正式表述）

**模型层的有效判定为二值：STRONG vs MEDIUM。**
- 依据：模型从不输出 NONE（208 item 上 NONE 输出 0 次）
- **但不表述为"模型能力只到二值"** —— 因为程序在 NONE 上同样不可靠（0.404 误判），
  无法反证"三值本可达到而模型未达"
- 正确表述：**在现有标签质量下，可被稳定评测的刻度是二值**

## 四、NONE 界的待办（未解决，必须随结论引用）

NONE 界的可靠性**当前无法确证**，因为：
1. 模型不输出 NONE（0/24 召回）
2. 独立程序把 0.404 的 MEDIUM 误判为 NONE
3. 两套标注对 NONE 的判定标准不一致（§249：三批在一个机械桶上用三套映射）

⇒ **NONE 界需要独立标注实验**（专门标注"无证据"样本，而非从现有池中派生）。
在该实验完成前，NONE 不应计入任何验收口径。
